# PRIME Чекап — план и MVP

Каркас: **цель → три варианта по цене → своя сборка → день → карта → цикл возврата.**

---

## 1. Что слабое в решении GLM (сводка)

| # | Проблема | Как закрываем |
|---|---|---|
| 1 | Вход через «тему/орган», а не через цель | Верхний уровень — 4 цели: «Для себя», «Планируем беременность», «Справка 075», «Для родителей/ребёнка». Органы и анализы — внутренняя логика |
| 2 | Нет цены | Цена на каждом шаге: у варианта, в конструкторе (live-пересчёт), в «дубли убраны: −X ₸», в записи |
| 3 | Нет нового клиента | Сценарий A идёт без карты и без регистрации (регистрация только на шаге 7, до записи) |
| 4 | Удержание = только напоминания | Семья/пара, годовой цикл «пора повторить», карта с динамикой, после-кекап-путь (программа беременности) |
| 5 | Дедупликация как самоцель | Клиент видит её только как выгоду: «дубли убраны: −X ₸» и персональная цена ниже пакета |

## 2. Ядро продукта (домен)

### 2.1. Цели (вход)
1. **Для себя** — базовый чекап (до 40 / 40+ — разные пакеты).
2. **Планируем беременность** — она / он / пара.
3. **Справка 075** — фиксированный набор по действующему приказу МЗ РК. Цена и скорость — главное.
4. **Для родителей / ребёнка** — шаблоны по возрасту.

### 2.2. Три уровня на каждую цель
- **Минимум** — только метки «обязательно».
- **Рекомендуем** — обязательно + рекомендуем. **Выбран по умолчанию** (гипотеза, проверяем долей выбора).
- **Максимум** — всё, включая «по желанию».

У каждого уровня: цена, состав, время в клинике.

### 2.3. Метки позиций (атрибут в составе пакета, не в каталоге)
- `обязательно` — в «Минимуме», убирать нельзя (для 075 — вообще фиксируем).
- `рекомендуем` — в «Рекомендуем» по умолчанию, в конструкторе можно убрать.
- `по желанию` — только в «Максимум» и в конструкторе.

### 2.4. Правила дедупликации (движок — чистая функция, хорошо тестится)
Для позиции пакета проверяем карту пациента (результаты с `valid_until`):

| Состояние результата | Решение |
|---|---|
| Консультация/услуга (не анализ) | Всегда включаем (услугу не «повторяем по сроку») |
| `valid_until` < сегодня | Включаем |
| `status = abnormal` | Включаем + пометка «повторить, ранее было отклонение» |
| `status = borderline` | Включаем + пометка «на границе нормы, рекомендуем контрольный замер» |
| `status = ok` и `valid_until` >= сегодня | **Пропускаем**, копим экономию → «дубли убраны: −X ₸» |

Важно: `valid_until` берётся из каталога (`validity_months`), **утверждаются врачи PRIME** — в MVP это колонка CSV, не магия.

### 2.5. Персональная цена (существующий клиент)
`цена_персональная = цена_пакета(Рекомендуем) − сумма пропущенных валидных позиций`
Показываем три цифры рядом: пакет / её персональная (жирная, ниже) / расширенный.

### 2.6. День (маршрут)
- У каждой позиции: станция (забор крови / УЗИ / рентген / врач), `duration_min`, `prep` (натощак и т.п.).
- Маршрут = упорядоченные слоты: утром забор крови (натощак), потом УЗИ, потом врач. «Время в клинике» считается из маршрута.
- Слоты с ёмкостью: забор крови по утрам — ограниченная пропускная способность, запись резервирует слот → выравнивание пиков.
- Подготовка показывается до записи («натощак, после полуночи ничего не есть»).

### 2.7. Карта здоровья
- Список результатов: дата, значение, статус, «действует до».
- Динамика по ключевым показателям (ферритин, D, ТТГ) — просто «было → стало» по последним 2–3 значениям.
- Разбор простым языком после чекапа (MVP: шаблон по статусу результата; ИИ-разбор — фаза 3).
- Блок «пора повторить» — все позиции с `valid_until` в ближайшие 30 дней → это и есть триггер цикла возврата.

### 2.8. Цикл возврата
- Напоминание за N дней до `valid_until` («пора повторить ферритин»).
- Годовой чекап: раз в год пуш со списком «что пора обновить» по её карте.
- После чекапа «Планирование (Ж)» → напоминание «повторить ферритин через 3 месяца» + оффер программы ведения беременности.
- Пара: одно нажатие — две записи. Семья: общий аккаунт (MVP — только пара, семья — фаза 2).

## 3. MVP: что внутри, что снаружи

### Внутри MVP
1. **Сценарий A целиком**: 4 цели → 3 вопроса (пол, возраст, цель) → 3 варианта → конструктор с live-ценой и «дубли убраны: −X ₸» → уточнение жалоб (простая форма + rule-based предупреждение «вам нужен врач, а не чекап» по стоп-словам) → день/маршрут с подготовкой и датой → контакт (телефон/WhatsApp/Telegram) + согласие, регистрация только здесь → напоминание накануне + PDF-маршрут.
2. **Сценарий B**: демо-профиль Асель (полные данные) — без анкеты, «уже есть, не повторяем», персональная цена, оффер пары для Данияра, напоминания после чекапа.
3. **Справка 075**: фиксированный шаблон (сверить с приказом!) + дедуп по флюорографии и другим валидным позициям.
4. **Карта здоровья** (чтение + приём результатов вручную из админки).
5. **Напоминания** через Telegram-бота + cron.
6. **Метрики воронки** — события на каждый шаг (таблица `events`).
7. **PDF-маршрут** — и это же бесплатный вход «подбор за 60 секунд» без регистрации.

### Снаружи MVP (честно)
- **Платёж онлайн** — запись по телефону/мессенджеру, оплата в клинике.
- **ИИ-разбор свободного текста жалоб** — MVP: форма чекбоксов + стоп-слова; LLM с грейд-билдером — фаза 3.
- **Семейный аккаунт** (полный) — MVP только пара (2 записи в 1 клик).
- **Корпоративный канал** — отдельная ворка (шаблон + оптовый список сотрудников).
- **Динамика графиков, ИИ-разбор результатов, A/B-эксперименты** — фаза 2+.
- **Маркетинг** (2GIS, Instagram, Maps) — не продукт.

## 4. Сценарий A — шаги и логика системы

| Шаг | Клиент | Система |
|---|---|---|
| 1. Заход | 4 крупные кнопки-цели | Фиксируем `session_id`, событие `landing→goal` |
| 2. Три вопроса | Пол, возраст, цель. Без регистрации | Подбирает пакеты под цель+возраст (40+ — другой состав) |
| 3. Три варианта | «Минимум / Рекомендуем / Максимум»: цена, состав, время в клинике | «Рекомендуем» выбран по умолчанию |
| 4. Конструктор | Убирает/добавляет позиции, видит live-цену и «дубли убраны: −X ₸» (если карта есть) | Переисчисляет цену и маршрут на каждое действие |
| 5. Уточнение | Жалобы (необязательно) | Rule-based: стоп-слова (кровь, боль > N дней, температура…) → «вам нужен врач, а не чекап» + номер регистратуры |
| 6. День | Маршрут с временем, подготовка «натощак», выбор даты | Резервирует слоты; считаем «время в клинике» |
| 7. Контакт | Телефон/WhatsApp, согласие. **Регистрация только здесь** | Создаём пациента (или привязываем к существующему по телефону), статус `pending` |
| 8. После записи | — | Напоминание накануне (Telegram/СМС), PDF-маршрут на почту/мессенджер |
| 9. После чекапа | — | Результаты в карту (ручной ввод в MVP), разбор простым языком, ставим напоминания по `validity` |

Привлечение (гипотезы, не продукт MVP, но готовим точки): 075 и «чекап Астана/Алматы» в поиске, 2ГИС/Maps, Instagram+WhatsApp, корпоративные договоры. Бесплатный вход — «подбор за 60 секунд» с PDF без регистрации (это шаг 1–4 + кнопка «отправить PDF себе»).

## 5. Сценарий B — Асель Каримова (демо-профиль)

31 год, ж. Клиент PRIME с 2024. Планирует беременность через 3–6 мес. Муж Данияр (33) — клиент, связан как семья.

| Дата | Что | Результат | Статус | Действует до |
|---|---|---|---|---|
| март 2024 | Базовый чекап до 40 | В норме | ok | истёк |
| нояб 2025 | Гинеколог, цитология, УЗИ МТ | Без патологии | ok | нояб 2026 |
| апр 2026 | Ферритин, витамин D | Ферритин на нижней границе, D снижен | borderline / abnormal | окт 2026 |
| авг 2026 | ОАК, ТТГ, глюкоза | В норме | ok | нояб 2026 |

Нажатие «Планирую беременность» (система, без анкеты):
1. Готовый список пакета «Планирование (Ж)».
2. «Уже есть, не повторяем»: ОАК, ТТГ, глюкоза, цитология, УЗИ МТ (все ok и валидны до нояб–дек 2026).
   - Консультации (гинеколог) не дедуплицируются — это услуга, её берём свежую.
3. Добавляем недостающее: TORCH, группа+резус, инфекции по списку, консультация по итогам.
4. Пара: «Записать Данияра на тот же день?» → андролог/уролог, спермограмма, группа крови.
5. Три цены (ниже — примерный расчёт, **цены-заглушки до прайса PRIME**):
   - Пакет «Планирование (Ж)» ≈ **97 500 ₸**
   - Персональная Асель (дубли −30 000 ₸) ≈ **67 500 ₸**
   - Расширенный (персональная + биохимия 15 000 + ферритин 7 500 «повтор, был на границе» + витамин D 9 000 «повтор, был снижен») ≈ **99 000 ₸**
   - Данияр (пара) ≈ **29 500 ₸** → пара итого ≈ **97 000 ₸**
6. После чекапа: напоминание «повторить ферритин через 3 месяца» + оффер программы ведения беременности.

**Правило-ловушка, которое важно зафиксировать:** abnormal/borderline НЕ дедуплицируются. Ферритин и витамин D у Асель как раз такие — расширенный пакет честно их добавляет с пометкой, а не прячет.

Справка 075 для своего: фиксированный набор по приказу, пометки «уже есть» (напр., флюорография в этом году), состав **обязательно сверить с действующим приказом МЗ РК** — это входной документ для MVP.

## 6. Модель данных (MVP)

```
patients        (id, phone UQ, first_name, last_name, birth_date, sex, tg_id, family_id, created_at)
families        (id)
tests           (code PK, name, category, price_kzt, validity_months, prep, station, duration_min, is_consult)
goals           (code PK: for_myself | pregnancy_f | pregnancy_m | cert_075 | parents_child, name)
packages        (code PK, goal_code, level: min|rec|max, name, package_price_kzt NULL)  -- цена по умолчанию = сумма позиций
package_items   (package_code, test_code, label: required|recommended|optional)
results         (id, patient_id, test_code, exam_date, value_text, status: ok|borderline|abnormal, valid_until)
bookings        (id, patient_id, date, status: pending|confirmed|canceled|done,
                 total_kzt, dedup_saved_kzt, consent_at, meta jsonb)
booking_items   (booking_id, test_code, price_kzt, skipped, skip_reason)
slots           (id, date, time_from, time_to, station, capacity, booked)
reminders       (id, patient_id, type: repeat|annual|pregnancy_program, due_date, source_result_id, status)
events          (id, session_id, step, meta jsonb, ts)          -- воронка
```

Модель пары = `families` + запись обоих пациентов в одну `family_id`; оффер пары — UI-кнопка, создающая вторую запись с той же датой.

## 7. Стек (MVP)

- **Backend:** Go + chi + pgx, Postgres. (Репо уже Go — остаёмся в стэке.)
- **Frontend:** server-rendered Go-шаблоны + HTMX, mobile-first (клиенты приходят с телефона из Instagram/2ГИС/Maps). Конструктор: HTMX-рефетч блока цены/маршрута.
- **PDF-маршрут:** gofpdf + DejaVu Sans (кириллица). Альтернатива — HTML→PDF через headless Chrome, если захотим красивее.
- **Напоминания:** robfig/cron в Go + Telegram Bot API (опыт уже есть). СМС-фолбэк — фаза 2.
- **Админка (минимум):** CRUD каталога + пакетов + приём результатов пациента. MVP может быть CSV-import + пара страниц.
- **Развёртывание:** 1 VPS, docker-compose (app + postgres), домен, Let's Encrypt.

## 8. Милиstones

### M1 — «цена на каждом шаге» (неделя 1)
Каталог (CSV-import), 4 цели × 3 пакета, движок цен и дедупликации с unit-тестами, сценарий A шаги 1–4 (цель → варианты → конструктор с live-ценой и «−X ₸»).
**Acceptance:** новый человек без регистрации за <60 сек доходит до трёх цен; дедуп-движок покрыт тестами (окна валидности, abnormal/borderline, консультации).

### M2 — «запись без телефона» (неделя 2)
Шаги 5–8: форма жалоб + стоп-слова, маршрут со слотами и подготовкой, запись (телефон/Telegram + согласие, регистрация), PDF-маршрут, напоминание накануне. Сценарий B: демо-профиль Асель, «уже есть», персональная цена, оффер пары.
**Acceptance:** полная запись A и B без звонка; PDF уходит; Асель видит −30 000 ₸ (заглушки) и оффер Данияра.

### M3 — «карта и возврат» (неделя 3)
Карта здоровья (результаты, valid_until, «было→стало», блок «пора повторить»), приём результатов из админки, разбор простым языком (шаблоны), напоминания по срокам, CSAT после чекапа, события воронки на все шаги.
**Acceptance:** через 29 дней после чекапа клиент получает «пора повторить X»; в дашборде видны конверсии по шагам воронки.

Соло-разработчик: **~3 недели** до работающего MVP. Сокращённый вариант (только A + 075, без B и карты): 2 недели.

## 9. Метрики (воронка + деньги)

События: `landing → goal → options → constructor → (pdf_free) → booking_form → booked → arrived → repeat`.

| Метрика | Зачем |
|---|---|
| Конверсия шагов воронки | Где теряем |
| Средний чек + доля выбора «Рекомендуем» | Главный рычаг среднего чека |
| Доля, убрал в конструкторе / добавил | Какие позиции «не тянут» |
| Доля «дубли убраны» (записей с экономией) | Дедуп как выгода |
| Принятие оффера пары | Рычаг «пара = 2 записи» |
| Время в клинике, время обработки заявки | Операционка |
| Конверсия «подбор за 60 секунд (PDF без рег)» → запись | Бесплатный вход |
| Конверсия напоминания → повторная запись | Цикл возврата |
| CSAT после чекапа | Доверие |

Дашборд MVP: одна таблица по дням (таблица `events` + SQL-агрегаты). Без BI.

## 10. Гипотезы и как проверяем

1. **Цена убирает барьер** → конверсия `options→booked` у нас vs текущий «позвонить и выяснить» (справка у регистратуры).
2. **«Рекомендуем» по умолчанию работает** → доля выбора уровня; если «Минимум» > 40% — пересмотреть состав/цены.
3. **Пара в 1 клик** → доля принятия оффера; цель > 25% пар.
4. **−X ₸ продаёт доверие** → CSAT-комментарий «уважительно/не навязали лишнего»; доля повторных обращений.
5. **«Пора повторить» конвертит** → напоминание → запись в 30 дней.
6. **60-секундный PDF-подбор** → доля PDF-сессий, дошедших до записи без звонка.

## 11. Риски / что утвердить до M1

1. **Прайс PRIME** — без него все «−X ₸» фикция. Нужен файл (xlsx/csv) → импортируем в каталог, пересчитываем примеры.
2. **Состав справки 075** — сверить с действующим приказом МЗ РК (версия приказа, список документов: флюорография, ЭКГ, осмотры, нарколог/психиатр и т.д.).
3. **Сроки валидности анализов** — утверждаются врачи PRIME (в демо: ОАК/ТТГ/глюкоза 3 мес, цитология/УЗИ 12 мес, ферритин/D 6 мес — всё «условно»).
4. **Честный минус дедупа** (меньше чек «здесь и сейчас») — компенсируем конверсией, парой, LTV. Решение для руководства: не показывать менеджерам KPOV на «повторных анализах», а на LTV 12 мес.

## 12. Что нужно от PRIME, чтобы стартовать M1

1. Прайс по пакетам и позициям (файл) — заменим заглушки в `data/catalog_template.csv`.
2. Действующий состав справки 075 (приказ/версия).
3. Врачебное утверждение сроков валидности по ключевым анализам.
4. Пропускная способность станций (забор крови/УЗИ/врач) в утренние часы — для слотов.
5. Контакт для подтверждения записей (WhatsApp/Telegram регистратуры).
